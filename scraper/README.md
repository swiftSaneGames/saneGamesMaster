# Reference-research prompt

Use this as an evidence-first analyst brief, not permission to scrape restricted services.

Study a lawfully accessible reference game. Prefer direct play through available tooling. If that is unavailable, inspect accessible gameplay recordings, official descriptions and relevant reviews. Ask the owner for a focused recording only when important mechanics remain unclear. Do not claim direct play when none occurred.

Record the reference title, publisher, platform, version/date when known, URLs, evidence type and timestamps. Describe the core loop, controls, progression, economy, level variation, difficulty, onboarding, feedback, ads and accessibility. Separate observation from inference. Propose original improvements and differences in mechanics, art, narrative and progression.

Use supported download evidence with its geography, time window and method. Label estimates; do not invent sales ranks or equate lifetime downloads with current popularity. Check the permitted access method before automation. Never bypass authentication, paywalls, bot restrictions or extract proprietary code/assets. Do not request competitor login credentials.

Keep private findings and project-specific design briefs in the private game repository. Publish only reviewed, non-sensitive reusable research methodology here. Output a concise handoff with evidence gaps, originality notes, feasibility concerns and suggested acceptance criteria.
